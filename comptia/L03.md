# Chapter 3: Security Applications and Devices

## บทนำ

บทนี้มุ่งอธิบายเทคโนโลยีและกลไกสำคัญที่ใช้เพื่อปกป้องระบบสารสนเทศในสภาพแวดล้อมองค์กรยุคใหม่ มาตรการด้านความมั่นคงปลอดภัยถูกออกแบบให้ทำงานแบบหลายชั้นเพื่อลดความเสี่ยงจากภัยคุกคาม ทั้งในระดับอุปกรณ์ผู้ใช้ปลายทาง เครือข่าย และข้อมูล โดยระบบที่ดีต้องสามารถตรวจจับ ป้องกัน และตอบสนองต่อเหตุการณ์ด้านความปลอดภัยได้อย่างมีประสิทธิภาพ

## วัตถุประสงค์การเรียนรู้

ผู้อ่านจะสามารถ

* อธิบายจุดประสงค์ของแอปพลิเคชันและอุปกรณ์รักษาความปลอดภัยทั่วไป
* แยกความแตกต่างระหว่างเครื่องมือป้องกันบนโฮสต์และบนเครือข่าย
* เปรียบเทียบการทำงานของ IDS และ IPS
* อธิบายแนวคิดการเข้ารหัส การป้องกันข้อมูลรั่วไหล และความปลอดภัย BIOS/UEFI
* ประยุกต์แนวปฏิบัติการป้องกันข้อมูลในอุปกรณ์จัดเก็บและสื่อแบบถอดได้

## 3.1 ภาพรวมระบบป้องกันแบบหลายชั้น (Defense in Depth)


**ระดับโฮสต์:** ระดับโฮสต์มุ่งเน้นการป้องกันภัยคุกคามที่เกิดขึ้นโดยตรงกับอุปกรณ์ผู้ใช้ เช่น คอมพิวเตอร์ แล็ปท็อป หรือเซิร์ฟเวอร์ หลักคิดสำคัญคือ “การปกป้องปลายทาง” (Endpoint Security) โดยถือว่าเครื่องปลายทางเป็นด่านแรกและด่านสุดท้ายในการป้องกันภัยมัลแวร์หรือการโจมตีเชิงรุก เครื่องมือสำคัญในระดับนี้ได้แก่โปรแกรมป้องกันมัลแวร์ที่ใช้เทคนิค signature-based และ heuristic-based เพื่อตรวจจับพฤติกรรมไม่พึงประสงค์ รวมถึงไฟร์วอลล์ส่วนบุคคลที่ควบคุมทราฟฟิกเข้า-ออกอุปกรณ์ตามนโยบายความปลอดภัย นอกจากนี้ ระบบ Endpoint Detection and Response (EDR) ยังมีบทบาทสำคัญในการตรวจสอบกิจกรรมภายในเครื่อง วิเคราะห์เหตุการณ์ย้อนหลัง และตอบสนองต่อภัยคุกคามในเชิงรุก แนวคิดพื้นฐานในระดับนี้คือ Zero Trust บนอุปกรณ์ (Zero Trust Endpoint) คือไม่เชื่อถือกิจกรรมหรือไฟล์ใดโดยอัตโนมัติ ต้องผ่านการตรวจสอบและยืนยันก่อนเสมอ การเสริมการป้องกันในระดับโฮสต์อย่างแข็งแรงช่วยลดความเสี่ยงจากมัลแวร์ การโจมตีผ่านผู้ใช้ และภัยคุกคามภายในองค์กรได้อย่างมีประสิทธิภาพ

### ตัวอย่างสถานการณ์ระดับโฮสต์ (Endpoint/Host Layer)

**สถานการณ์:**
พนักงานคลิกไฟล์แนบในอีเมลฟิชชิงที่ปลอมตัวเป็นใบแจ้งหนี้ ส่งผลให้มัลแวร์ประเภท ransomware เริ่มพยายามเข้ารหัสไฟล์ในเครื่อง

**มาตรการที่ทำงาน:**

* โปรแกรมป้องกันมัลแวร์ตรวจจับพฤติกรรมเข้ารหัสไฟล์ผิดปกติและกักกันไฟล์รันสคริปต์ดังกล่าว
* ระบบ EDR บันทึกเหตุการณ์ รัน playbook การตอบสนองอัตโนมัติ และแจ้ง SOC
* ไฟร์วอลล์ส่วนบุคคลบล็อกการเชื่อมต่อ C2 server ที่มัลแวร์พยายามเชื่อมไปยังอินเทอร์เน็ต

**ผลลัพธ์:**
การโจมตีถูกยับยั้งก่อนที่ข้อมูลในเครื่องและระบบอื่นจะถูกเข้ารหัส

**มุม Securityที่เกี่ยวข้อง:**
Malware analysis, Endpoint protection, Host-based firewall, Incident response, EDR

**ระดับเครือข่าย:**  ระดับเครือข่ายเน้นการควบคุม ตรวจสอบ และป้องกันการสื่อสารข้อมูลระหว่างระบบภายในและภายนอกองค์กร ทฤษฎีพื้นฐานคือการสร้าง “เส้นรอบวงความปลอดภัย” (Security Perimeter) แม้ในยุค modern network ที่มี Zero-Trust, cloud และ remote work แนวคิดนี้ยังคงสำคัญ เพียงแต่ปรับเป็น perimeter-less security แทน องค์ประกอบหลักประกอบด้วยไฟร์วอลล์ซึ่งทำงานตามหลัก rule-based filtering และ stateful inspection เพื่อตัดสินว่าทราฟฟิกควรอนุญาตหรือปฏิเสธ ส่วนระบบ Intrusion Detection System (IDS) ใช้แนวคิด threat pattern analysis เพื่อตรวจจับความผิดปกติและแจ้งเตือน ขณะที่ Intrusion Prevention System (IPS) พัฒนาจาก IDS โดยเพิ่มความสามารถในการ “หยุดยั้ง” การโจมตีทันที ทั้งนี้ ตัวกรองเนื้อหา (content filtering) สนับสนุนการจำกัดการเข้าถึงเว็บหรือไฟล์อันตรายบนพื้นฐานของ policy-driven control การบูรณาการเทคโนโลยีเหล่านี้ทำให้เครือข่ายสามารถตอบสนองต่อภัยคุกคามได้ตั้งแต่ขอบระบบจนถึงจุดผู้ใช้ปลายทาง

### ตัวอย่างสถานการณ์ระดับเครือข่าย (Network Defense Layer)

**สถานการณ์:**
แฮกเกอร์พยายามสแกนพอร์ตเซิร์ฟเวอร์องค์กรพร้อมส่ง payload เพื่อ exploit ช่องโหว่ใน web server

**มาตรการที่ทำงาน:**

* Firewall ปฏิเสธการเชื่อมต่อที่ผิดปกติจาก IP ที่ไม่อยู่ใน whitelist
* NIDS ตรวจจับ pattern การสแกนพอร์ตและแจ้งเตือน
* IPS block packet อันตรายและ drop การเชื่อมต่อแบบ real-time
* Content filter ปิดกั้นการ download script อันตรายในกรณีหลุดรอด

**ผลลัพธ์:**
ระบบยังคงปลอดภัย แม้มีความพยายามตรวจ probing และ exploit



**ระดับข้อมูล:** ระดับข้อมูลคือหัวใจของ Defense in Depth เพราะวัตถุประสงค์สูงสุดของการโจมตีส่วนใหญ่คือการเข้าถึง แก้ไข หรือขโมยข้อมูล ทฤษฎีหลักที่ใช้ในระดับนี้คือ CIA Triad ซึ่งประกอบด้วยความลับ (Confidentiality) ความถูกต้อง (Integrity) และความพร้อมใช้งาน (Availability) มาตรการสำคัญคือการเข้ารหัสข้อมูล (Encryption) ไม่ว่าจะเป็นข้อมูลนิ่ง (data-at-rest) หรือข้อมูลที่เคลื่อนที่ (data-in-transit) เพื่อลดความเสี่ยงหากข้อมูลรั่วไหลหรือถูกดักจับ นอกจากนี้ ระบบการควบคุมสิทธิ์การเข้าถึง (Access Control) ใช้หลัก least privilege และ role-based access control เพื่อให้เฉพาะผู้มีสิทธิ์เท่านั้นที่เข้าถึงข้อมูลได้ ระบบ Data Loss Prevention (DLP) ทำงานบนทฤษฎี policy-enforced monitoring คือกำกับการเคลื่อนย้ายข้อมูลและป้องกันการรั่วไหลโดยตรวจสอบรูปแบบข้อมูลและพฤติกรรมการใช้งาน การป้องกันระดับข้อมูลจึงช่วยให้แม้ระบบอื่นถูกเจาะ ข้อมูลสำคัญยังได้รับการคุ้มครองอย่างมีประสิทธิภาพ

### ตัวอย่างสถานการณ์ระดับข้อมูล (Data Security Layer)

**สถานการณ์:**
พนักงานพยายามคัดลอกไฟล์ข้อมูลลูกค้าสำคัญลง USB drive เพื่อนำออกนอกองค์กร

**มาตรการที่ทำงาน:**

* Access control ตรวจสอบสิทธิ์และจำกัดเฉพาะข้อมูลที่จำเป็น
* DLP ตรวจจับความพยายามส่งออกข้อมูลที่เข้าข่ายข้อมูลอ่อนไหว (PII)
* ระบบบล็อกการคัดลอกข้อมูลไปยัง USB และแจ้งเตือนทีม Security
* แม้ไฟล์หลุดออกไป ข้อมูลยังถูกเข้ารหัส (Encryption at rest)

**ผลลัพธ์:**
ข้อมูลไม่ถูกนำออกไปและมีหลักฐานเหตุการณ์พร้อมดำเนินการสอบสวน

**มุม Security+ ที่เกี่ยวข้อง:**
Data protection, DLP, Access control, Encryption, Insider threat mitigation


### ความเชื่อมโยงภาพรวมตามแนวคิด Defense in Depth

แม้ผู้โจมตีหรือผู้ใช้ภายในจะพยายามละเมิดระบบในชั้นหนึ่ง ระบบยังมีมาตรการสำรองในหลายระดับ เช่น

| ชั้นป้องกัน | บทบาทสำคัญ                                   |
| ----------- | -------------------------------------------- |
| Host        | ตรวจจับ/หยุดพฤติกรรมผิดปกติบนอุปกรณ์         |
| Network     | ควบคุมทราฟฟิก ป้องกันการบุกรุกจากภายนอก      |
| Data        | ปกป้องข้อมูลโดยตรง แม้ระบบอื่นถูก compromise |

ผลลัพธ์คือองค์กรยังคงควบคุมความเสี่ยงได้อย่างมั่นคงและตรวจสอบย้อนหลังได้ตามหลัก Digital Forensics



## 3.2 สื่อจัดเก็บข้อมูลแบบถอดได้ (Removable Media)

อุปกรณ์เช่น USB flash drive และ external HDD มีความเสี่ยงด้านมัลแวร์และการนำข้อมูลออกนอกองค์กร ดังนั้นควรใช้มาตรการดังนี้

### เข้ารหัสข้อมูลทุกครั้งก่อนจัดเก็บ

การเข้ารหัสข้อมูลบนสื่อแบบถอดได้เป็นการนำแนวคิด *Confidentiality* จากกรอบ CIA Triad มาใช้โดยตรง หมายถึงทำให้ข้อมูลอยู่ในรูปแบบที่ไม่สามารถอ่านได้หากไม่มีคีย์ถอดรหัส ขั้นตอนนี้ช่วยลดความเสี่ยงเมื่ออุปกรณ์สูญหาย ถูกขโมย หรือถูกเข้าถึงโดยไม่ได้รับอนุญาต แนวคิดสำคัญที่เกี่ยวข้องคือ **encryption at rest** ซึ่งครอบคลุมการปกป้องข้อมูลเมื่อไม่ได้ถูกใช้งาน อัลกอริทึมที่นิยมคือ AES-256 และการใช้งานมักอยู่ในรูปแบบ Full-Disk Encryption (FDE) หรือ File-Level Encryption ตัวอย่างเช่น องค์กรที่กำหนดให้พนักงานใช้ BitLocker หรือ VeraCrypt บน USB drive เพื่อป้องกันข้อมูลลูกค้า หาก USB ตกหล่นในพื้นที่สาธารณะ ผู้พบเห็นจะไม่สามารถเข้าถึงข้อมูลได้ ทำให้ลดความเสี่ยงต่อการละเมิดข้อมูลและบทลงโทษจากกฎหมายคุ้มครองข้อมูลส่วนบุคคล


###  จำกัดหรือปิดการใช้งานพอร์ต USB ตามความจำเป็น

หลักการ Zero-Trust และ Least Privilege ถูกนำมาใช้ในมาตรการนี้ โดยถือว่าอุปกรณ์ทุกชนิดไม่ควรเชื่อถือจนกว่าจะตรวจสอบความปลอดภัย การปิดหรือจำกัดพอร์ต USB ช่วยลดโอกาสที่มัลแวร์จากอุปกรณ์ภายนอกจะเข้าสู่ระบบ รวมถึงป้องกันการคัดลอกข้อมูลออกนอกองค์กรโดยไม่ได้รับอนุญาต องค์กรอาจใช้ Group Policy หรือ Endpoint Management System เพื่อควบคุมสิทธิ์การใช้งานพอร์ต USB ตัวอย่างเช่น บริษัทด้านการเงินอนุญาตเฉพาะพอร์ต USB ที่ลงทะเบียนแล้วเท่านั้น และปิดพอร์ตทั้งหมดบนเครื่องฝ่ายขายเพื่อป้องกันการรั่วไหลของฐานข้อมูลลูกค้า แนวทางนี้มักใช้ในหน่วยงานรัฐ โรงพยาบาล และภาคการเงินที่มีข้อมูลอ่อนไหว

### กำหนดนโยบายการใช้งานสื่อถอดได้และบันทึกการใช้งาน

มาตรการเชิงนโยบายเป็นส่วนของ Governance ในกรอบ NIST Cybersecurity Framework โดยระบุเงื่อนไข วิธีปฏิบัติ และข้อห้ามที่ชัดเจนในการใช้สื่อถอดได้ นโยบายควรรวมการอนุมัติ การตรวจสอบอุปกรณ์ก่อนใช้งาน การเก็บบันทึกการใช้งาน และมาตรการลงโทษหากฝ่าฝืน แนวคิดสำคัญคือ **accountability และ auditability** ซึ่งช่วยให้สามารถติดตามว่าใครนำข้อมูลอะไรออกไปเมื่อใด ตัวอย่างเช่น โรงพยาบาลอาจกำหนดให้เจ้าหน้าที่ต้องลงทะเบียน USB drive ต่อฝ่าย IT พร้อมเหตุผลการใช้งาน และระบบจะบันทึก log การเสียบ-ถอดอุปกรณ์ทุกครั้งเพื่อให้ตรวจสอบย้อนหลังได้หากพบความผิดปกติ

###  ใช้ระบบ DLP เพื่อตรวจสอบการส่งข้อมูลไปยังอุปกรณ์เหล่านี้

Data Loss Prevention (DLP) ใช้หลักการ **policy-based data inspection** และ **content recognition** เช่น pattern matching, fingerprinting หรือ machine learning เพื่อตรวจจับข้อมูลอ่อนไหว เช่น เลขบัตรประชาชน เลขบัตรเครดิต หรือเอกสารลับขององค์กร ระบบสามารถบล็อกหรือเตือนเมื่อผู้ใช้พยายามคัดลอกข้อมูลไปยัง USB drive ตัวอย่างเช่น บริษัทเทคโนโลยีตั้งกฎให้ DLP หยุดการโอนเอกสารโค้ดโปรแกรมไปยังอุปกรณ์ภายนอกโดยอัตโนมัติ และแจ้งเตือนทีม Security หากพบความพยายามซ้ำ วิธีนี้ช่วยลดความเสี่ยงด้าน insider threat และปกป้องทรัพย์สินทางปัญญาขององค์กร

## 3.3 ที่จัดเก็บข้อมูลบนเครือข่าย


### **Network Attached Storage (NAS)**

NAS เป็นระบบจัดเก็บข้อมูลที่ให้บริการในระดับไฟล์ (File-level Storage) ผ่านเครือข่ายภายในองค์กร โดยคลientsเข้าถึงผ่านโปรโตคอล เช่น SMB, NFS หรือ FTP แนวคิดพื้นฐานของ NAS มาจากสถาปัตยกรรม **centralized storage** ที่ช่วยให้การแชร์ไฟล์และสำรองข้อมูลเป็นระบบมากขึ้น ลดความซ้ำซ้อนของข้อมูลและปรับปรุงการบริหารจัดการไฟล์ ส่วนสำคัญเชิงทฤษฎีคือ **High Availability และ Fault Tolerance** ซึ่งมักใช้ RAID เพื่อให้ระบบยังทำงานได้แม้ HDD บางลูกเสียหาย องค์กรยังใช้ **access control และ encryption** เพื่อรักษาความลับและป้องกัน unauthorized access ตามหลักการ CIA Triad โดยเฉพาะ Confidentiality และ Integrity

**ตัวอย่าง:**
บริษัทออกแบบสถาปัตยกรรมใช้ NAS เพื่อให้ทีมแชร์ไฟล์ CAD ขนาดใหญ่ และตั้ง RAID-5 เพื่อให้ระบบยังเข้าถึงไฟล์ได้แม้มีฮาร์ดดิสก์ชำรุดหนึ่งลูก พร้อมกำหนดสิทธิ์การเข้าถึงไฟล์ตามแผนก เช่น ฝ่ายขายไม่สามารถเข้าถึงไฟล์งานฝ่ายออกแบบ


### **Storage Area Network (SAN)**

SAN เป็นโครงสร้างพื้นฐานจัดเก็บข้อมูลระดับองค์กรที่ออกแบบสำหรับ **block-level storage** เหมาะสำหรับระบบที่ต้องการประสิทธิภาพสูง เช่น Virtualization, Database และ ERP แนวคิดหลักคือ **dedicated storage fabric** ที่แยกออกจากเครือข่ายผู้ใช้งานทั่วไปเพื่อเพิ่ม throughput และลด latency โดยใช้ Fibre Channel หรือ iSCSI ทฤษฎีด้านความมั่นคงปลอดภัยที่เกี่ยวข้องคือ **network segmentation และ isolation** ซึ่งช่วยลดผิวการโจมตี (attack surface) และป้องกันการเข้าถึงข้อมูลสำคัญโดยไม่ได้รับอนุญาต องค์กรยังใช้การเข้ารหัสข้อมูลและระบบ logging เพื่อตรวจสอบ audit trail รองรับ Compliance ตามมาตรฐาน เช่น ISO 27001 และ GDPR

**ตัวอย่าง:**
ศูนย์ข้อมูลมหาวิทยาลัยใช้ SAN สำหรับระบบ VM และฐานข้อมูลนักศึกษา โดยตั้งเครือข่าย Fibre Channel แยกจาก LAN ปกติ พร้อมบังคับใช้ encryption-at-rest และ audit log เพื่อให้ตรวจสอบกิจกรรมการเข้าถึง storage ได้หากเกิดเหตุผิดปกติ เช่น ผู้ดูแลระบบพยายามคัดลอกฐานข้อมูลโดยไม่ได้รับอนุญาต

## 3.4 ไฟร์วอลล์แบบซอฟต์แวร์ (Software Firewalls)

ไฟร์วอลล์ที่ทำงานบนเครื่องผู้ใช้เพื่อควบคุมทราฟฟิกเข้าออก เช่น

### **Windows Firewall**

Windows Firewall คือไฟร์วอลล์เชิงซอฟต์แวร์ที่ติดมากับระบบปฏิบัติการ Windows โดยอาศัยหลักการ *stateful packet inspection* และ *rule-based access control* เพื่อควบคุมทราฟฟิกเข้าออกเครื่องคอมพิวเตอร์ตามนโยบายด้านความมั่นคงปลอดภัย แนวคิดพื้นฐานคือ Zero Trust for network connections โดยไม่อนุญาตการเชื่อมต่อใดๆ นอกจากรายการที่ได้รับอนุญาตอย่างชัดเจน ผู้ดูแลระบบสามารถกำหนดกฎตามโปรโตคอล พอร์ต แอปพลิเคชัน หรือ IP Address ได้ อีกทั้งรองรับการทำงานรวมกับ Windows Defender และ Group Policy เพื่อควบคุมการตั้งค่าในระดับองค์กร ตัวอย่างเช่น องค์กรเปิดใช้งาน Windows Firewall เพื่อบล็อกพอร์ต 445 จากเครือข่ายสาธารณะเพื่อลดความเสี่ยงจาก ransomware เช่น WannaCry และอนุญาตเฉพาะ VPN traffic เพื่อเข้าถึงทรัพยากรภายใน



###  **PF/IPFW บน macOS**

Packet Filter (PF) และ IP Firewall (IPFW) เป็นระบบไฟร์วอลล์พื้นฐานใน macOS โดย PF เป็นกลไกหลักใน macOS รุ่นปัจจุบัน ซึ่งใช้วิธี *stateful filtering* และ *network address translation (NAT)* รวมถึงรองรับการทำ traffic shaping แนวคิดทางทฤษฎีคือ “policy-driven traffic control” ที่ให้ผู้ดูแลระบบกำหนดกฎการอนุญาตหรือปฏิเสธการเชื่อมต่อผ่านไฟล์กำหนดค่า ตัวอย่างเช่น นักพัฒนาในบริษัทใช้ MacBook ในการพัฒนาระบบเว็บภายในองค์กร จึงตั้ง PF ให้อนุญาตเพียง HTTP/HTTPS จากเครือข่ายองค์กร และบล็อก incoming traffic ทั้งหมดจากเครือข่ายสาธารณะเพื่อป้องกันการสแกนพอร์ตหรือช่องโหว่จากภายนอก ทั้งนี้ macOS ยังผนวกไฟร์วอลล์เข้ากับระบบรักษาความปลอดภัย OS อย่าง sandboxing และ Gatekeeper เพื่อยกระดับความปลอดภัยแบบหลายชั้น


###  **iptables / firewalld บน Linux**

iptables และ firewalld เป็นระบบไฟร์วอลล์บน Linux ที่ทำงานบนแนวคิด *kernel-level packet filtering* โดย iptables อนุญาตให้สร้างกฎทีละรายการผ่าน command-line ในขณะที่ firewalld ให้การจัดการแบบ dynamic zones และ runtime configuration เพื่อให้ใช้งานง่ายขึ้น แนวคิดทฤษฎีสำคัญคือ **Least Privilege Networking** คือเปิดเฉพาะพอร์ตที่จำเป็นต่อบริการ เช่น SSH, HTTPS และบล็อกที่เหลือทั้งหมด ระบบนี้มักใช้ในเซิร์ฟเวอร์ที่ต้องมีความมั่นคงปลอดภัยสูง เช่น Web server, Database server ตัวอย่างเช่น ผู้ดูแลระบบตั้ง firewalld ให้อนุญาตเฉพาะ HTTP/HTTPS บนเซิร์ฟเวอร์ Apache Linux และจำกัดการเข้าถึง SSH ด้วย Allow-listed IP เพื่อลดการโจมตี brute-force จากอินเทอร์เน็ต

ด้านล่างเป็นตารางเปรียบเทียบ **Windows Firewall vs macOS PF vs Linux iptables/firewalld** จัดทำในรูปแบบวิชาการ กระชับ ชัดเจน

| ประเด็นเปรียบเทียบ                      | Windows Firewall                                             | macOS PF                                                | Linux iptables / firewalld                                               |
| --------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------- | ------------------------------------------------------------------------ |
| ประเภท                                  | Personal Firewall / Host-based Firewall                      | Host-based Packet Filter                                | Kernel-level Packet Filter / Host-based Firewall                         |
| กลไกหลัก                                | Stateful inspection, rule-based filtering                    | Stateful filtering, NAT, packet filtering               | Netfilter framework, rule-based packet filtering, NAT, zones (firewalld) |
| การกำหนดค่า                             | GUI, PowerShell, Group Policy                                | Configuration files (pf.conf), CLI tools                | CLI commands (iptables), dynamic zones & CLI/GUI (firewalld)             |
| เหมาะสำหรับ                             | ผู้ใช้ทั่วไปและองค์กร Windows domain                         | ผู้ใช้ macOS, นักพัฒนา, องค์กร Apple ecosystem          | เซิร์ฟเวอร์, DevOps, ระบบเครือข่าย, Cloud infrastructure                 |
| จุดเด่น                                 | ใช้งานง่าย, บูรณาการกับ Defender, รองรับ GPO สำหรับองค์กร    | มีประสิทธิภาพสูง, เนทีฟใน BSD-based OS, ควบคุมกฎละเอียด | ความยืดหยุ่นสูง, ควบคุมได้ลึก, เหมาะสำหรับ production server             |
| จุดด้อย                                 | ความยืดหยุ่นต่ำกว่า Linux, ผู้ใช้ทั่วไปอาจไม่ปรับแต่งเชิงลึก | ต้องแก้ไขไฟล์ config ซึ่งมีความซับซ้อนสำหรับมือใหม่     | เรียนรู้ยาก, risk หากตั้งค่าผิด, iptables syntax ซับซ้อน                 |
| ตัวอย่างการใช้งาน                       | ควบคุม traffic ใน Windows endpoint, ป้องกัน ransomware       | Mac endpoint security, developer workstation            | ป้องกัน web server, database server, cloud instance เช่น AWS EC2         |
| ความสัมพันธ์กับระบบรักษาความปลอดภัยอื่น | ผสานกับ Windows Defender, SIEM, AD Security                  | ทำงานร่วมกับ Gatekeeper, SIP, sandboxing                | ผสานกับ SELinux / AppArmor, SIEM และระบบ monitoring ในองค์กร             |


### สรุปเชิงวิเคราะห์

ไฟร์วอลล์ทั้งสามแพลตฟอร์มสะท้อนถึงแนวคิด **policy-based network control และ Zero-Trust Network Access** แต่ระดับความยืดหยุ่นและความเหมาะสมแตกต่างกันตามสภาพแวดล้อมการใช้งาน Windows เน้นความเป็นมิตรต่อผู้ใช้และการบริหารในองค์กร ส่วน macOS PF มุ่งความเสถียรและความแม่นยำสำหรับงานพิเศษ ในขณะที่ Linux iptables/firewalld ให้ความสามารถขั้นสูงสำหรับงานเครือข่ายระดับองค์กรและศูนย์ข้อมูล

ด้านล่างเป็นตัวอย่างคำสั่งตั้งค่าไฟร์วอลล์บน **Windows, macOS, และ Linux** เพื่อให้เห็นภาพการใช้งานจริง (เหมาะสำหรับภาคปฏิบัติ Security+ / Lab)


###  **Windows Firewall (PowerShell)**

#### อนุญาตให้เข้าถึงบริการ HTTPS (พอร์ต 443)

```powershell
New-NetFirewallRule -DisplayName "Allow HTTPS" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow
```

#### บล็อกพอร์ต 445 (ป้องกัน Ransomware/Worm เช่น WannaCry)

```powershell
New-NetFirewallRule -DisplayName "Block SMB" -Direction Inbound -Protocol TCP -LocalPort 445 -Action Block
```

#### แสดงกฎไฟร์วอลล์ทั้งหมด

```powershell
Get-NetFirewallRule
```


###  **macOS PF (Packet Filter)**

#### เปิดใช้งาน PF

```bash
sudo pfctl -e
```

#### อนุญาตเฉพาะ SSH (พอร์ต 22) และบล็อกทั้งหมดอื่น

เพิ่มในไฟล์ `/etc/pf.conf`

```
block all
pass in proto tcp from any to any port 22
```

#### โหลดไฟล์ config ใหม่

```bash
sudo pfctl -f /etc/pf.conf
```

#### ดูสถานะ

```bash
sudo pfctl -s rules
```


###  **Linux iptables / firewalld**

### iptables ตัวอย่าง

#### อนุญาต SSH จาก IP เฉพาะ

```bash
sudo iptables -A INPUT -p tcp -s 192.168.1.50 --dport 22 -j ACCEPT
```

#### บล็อกพอร์ต 23 (Telnet)

```bash
sudo iptables -A INPUT -p tcp --dport 23 -j DROP
```

#### แสดงกฎทั้งหมด

```bash
sudo iptables -L -n
```
### firewalld ตัวอย่าง (CentOS, RHEL, Fedora)

#### อนุญาต HTTPS

```bash
sudo firewall-cmd --add-service=https --permanent
sudo firewall-cmd --reload
```

#### บล็อกพอร์ต 21 (FTP)

```bash
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" port port="21" protocol="tcp" reject'
sudo firewall-cmd --reload
```

#### แสดงกฎ

```bash
sudo firewall-cmd --list-all
```

## 3.5 ระบบตรวจจับการบุกรุก (IDS)

IDS ทำหน้าที่ตรวจสอบทราฟฟิกหรือบันทึกเหตุการณ์เพื่อค้นหาพฤติกรรมผิดปกติ

#### ✅ **HIDS (Host-based Intrusion Detection System)**

HIDS คือระบบตรวจจับการบุกรุกที่ทำงานบนอุปกรณ์ปลายทาง เช่น เซิร์ฟเวอร์หรือเครื่องคอมพิวเตอร์ของผู้ใช้ จุดสำคัญคือการตรวจสอบ *กิจกรรมภายในระบบปฏิบัติการ* เช่น log files, system calls, registry, integrity ของไฟล์ระบบ และโปรเซสที่รันอยู่ หลักคิดทางทฤษฎีคือ *Host Behavioral Monitoring* และ *File Integrity Monitoring (FIM)* ซึ่งสามารถตรวจจับความพยายามแก้ไขไฟล์สำคัญ เช่น `/etc/passwd` บน Linux หรือไฟล์ registry บน Windows ตัวอย่างเช่น ถ้ามีการแก้ไขไฟล์ system configuration โดยไม่มีเหตุผลหรือกระบวนการลึกลับเกิดขึ้นในเครื่องเซิร์ฟเวอร์ HIDS เช่น OSSEC หรือ Wazuh สามารถแจ้งเตือนผู้ดูแลระบบได้ ทฤษฎี Zero-Trust Endpoint ยังถูกนำมาใช้ เพื่อไม่เชื่อถือกิจกรรมใด ๆ บนเครื่องจนกว่าจะพิสูจน์ได้ว่าปลอดภัย ทำให้เหมาะกับการตรวจสอบภัยภายในองค์กรหรือการโจมตีที่หลุดจาก perimeter defense



#### ✅ **NIDS (Network-based Intrusion Detection System)**

NIDS ถูกติดตั้งในจุดยุทธศาสตร์ของเครือข่าย เช่น DMZ หรือ Core Switch เพื่อวิเคราะห์แพ็กเก็ตที่ผ่านเครือข่ายในแบบ real-time หลักคิดคือ *Network Visibility & Threat Monitoring* โดยตรวจจับพฤติกรรมผิดปกติ เช่น port scanning, packet manipulation หรือ malicious payload ผ่าน deep packet inspection ตัวอย่างเช่น เมื่อผู้โจมตีใช้เครื่องมือ Nmap เพื่อทำ network reconnaissance ระบบ NIDS เช่น Snort หรือ Suricata สามารถระบุ pattern ของการสแกนพอร์ตและเตือน SOC ได้ จุดแข็งคือสามารถมองเห็นการโจมตีที่กำลังเคลื่อนผ่านเครือข่ายแม้ยังไม่ถึง endpoint แต่ข้อจำกัดคือไม่สามารถตรวจจับภัยที่เกิดเฉพาะในเครื่อง หรือข้อมูลที่ถูกเข้ารหัส end-to-end โดยสมบูรณ์


### วิธีการตรวจจับ

#### ✅ **Signature-based Detection**

แนวคิด signature-based เหมือนระบบตรวจจับไวรัสแบบดั้งเดิม ใช้ฐานข้อมูลรูปแบบภัยคุกคาม เช่น hash, pattern ของคำสั่ง, หรือ sequence ของ packet เพื่อระบุการโจมตี ทฤษฎีสำคัญคือ *Pattern Matching & Known Threat Database* ซึ่งมีประสิทธิภาพในการตรวจจับภัยที่รู้จักแล้ว (known attacks) เช่น SQL injection payload แบบคลาสสิก `"OR '1'='1"` ตัวอย่างเช่น Snort โหลด signature rule เพื่อตรวจจับมัลแวร์ที่มีลักษณะใน packet เหมือนกับ Emotet แต่ข้อเสียคือไม่สามารถจับภัยใหม่หรือ zero-day ได้หากไม่มี signature ในฐานข้อมูล ทำให้การอัปเดต rule set เป็นสิ่งสำคัญ

#### ✅ **Policy-based Detection**

Policy-based IDS ใช้กฎความปลอดภัยที่องค์กรกำหนดเองเป็นหลัก เช่น ห้าม remote login หลังเวลาทำงาน หรือห้ามส่งข้อมูลออกจากเครือข่ายไปยัง IP ภายนอกโดยไม่ได้รับอนุญาต ทฤษฎีหลักคือ *Rule-driven Security Enforcement* และ **Access Control + Behavioral Rules** ตัวอย่างเช่น ระบบกำหนด policy ว่าบัญชี admin หาก login จาก IP ต่างประเทศถือว่าผิดปกติ แล้ว IDS จะเตือนทันทีหากเกิดเหตุการณ์นั้น เหมาะสำหรับองค์กรที่มี compliance สูง เช่น ธนาคาร โรงพยาบาล แต่ต้องมีผู้เชี่ยวชาญออกแบบกฎเพื่อให้เกิดประสิทธิภาพสูงสุด

#### ✅ **Anomaly-based Detection**

วิธีนี้อาศัยทฤษฎี *Statistical Baseline* และอัลกอริทึม machine learning เพื่อวิเคราะห์พฤติกรรมปกติของระบบ เช่น จำนวน connection ต่อวินาที หรือปริมาณ traffic ปกติ หากค่ามากผิดปกติ เช่น traffic เพิ่มขึ้นอย่างรวดเร็ว อาจสื่อถึง DoS/DDoS attack ตัวอย่างเช่น หากระบบฐานข้อมูลปกติรับ 200 query ต่อวินาที แต่เพิ่มเป็น 10,000 query ภายใน 10 วินาที IDS anomaly-based เช่น Suricata จะเตือนทันที จุดแข็งคือสามารถจับภัย zero-day แต่ต้องอาศัย baseline ที่เที่ยงตรงและอาจเกิด false positive ได้สูง

### ประเภทการแจ้งเตือน

#### ✅ **ประเภทการแจ้งเตือน: True Positive / False Positive / True Negative / False Negative**

การทำงานของ IDS ประเมินจากความแม่นยำในการจำแนกเหตุการณ์ โดยใช้หลัก *Binary Classification*

| ประเภท         | ความหมาย                       | ผลลัพธ์       |
| -------------- | ------------------------------ | ------------- |
| True Positive  | ตรวจจับภัยจริงได้ถูกต้อง       | ดีที่สุด      |
| False Positive | แจ้งเตือนกิจกรรมปกติว่าเป็นภัย | เกิด noise    |
| True Negative  | กิจกรรมปกติไม่ถูกแจ้งเตือน     | ปกติถูกต้อง   |
| False Negative | ภัยจริงแต่ระบบไม่ตรวจจับ       | อันตรายที่สุด |

**ตัวอย่าง:**

* True Positive: ระบบตรวจจับ ransomware และแจ้งเตือน
* False Positive: IDS แจ้งว่าการ backup ปกติเป็นการ exfiltration
* True Negative: internal DNS request ปกติถูกปล่อยผ่าน
* False Negative: malware ติดตั้ง backdoor แต่ IDS ไม่รู้จัก signature จึงไม่แจ้งเตือน

False negative คือความเสี่ยงสูงสุด เพราะแปลว่าผู้โจมตีเข้าได้โดยไม่ถูกตรวจพบ จึงต้องมีทั้ง signature-based และ anomaly-based ผสานกันเพื่อเพิ่มความครอบคลุม

## 3.6 ระบบป้องกันการบุกรุก (IPS)

### ✅ ระบบป้องกันการบุกรุก (Intrusion Prevention System: IPS)

ระบบป้องกันการบุกรุก (IPS) เป็นเทคโนโลยีรักษาความมั่นคงปลอดภัยเครือข่ายที่ทำงานในตำแหน่ง *inline* หมายถึงอยู่ในเส้นทางการรับส่งข้อมูลโดยตรง ทำให้สามารถตรวจสอบ วิเคราะห์ และ “หยุด” ทราฟฟิกที่เป็นอันตรายก่อนเข้าสู่ระบบปลายทางได้ทันที หลักคิดสำคัญของ IPS คือ **Proactive Security** หรือการป้องกันเชิงรุก ต่างจาก IDS ที่เน้นการตรวจจับและแจ้งเตือนเท่านั้น IPS สามารถดำเนินการแบบอัตโนมัติด้วยเทคนิค เช่น *packet dropping*, *connection termination*, *rate limiting*, และ *quarantine* เพื่อลดความเสี่ยงจากการโจมตี

จากมุมทฤษฎี IPS ใช้ทั้ง **Signature-based detection**, **Anomaly-based analysis**, และ **Behavior monitoring** เพื่อรับมือภัยคุกคามที่รู้จักและไม่รู้จัก เช่น DoS/DDoS, buffer overflow exploitation, brute-force login attempts และการส่ง payload อันตรายในระดับแอปพลิเคชัน (.SQL injection, XSS) ระบบนี้เป็นส่วนสำคัญของสถาปัตยกรรม Zero-Trust Network และ Secure Access Service Edge (SASE) ที่ต้องการควบคุมทราฟฟิกทุกช่องทางก่อนเข้าทรัพยากรสำคัญ

**ตัวอย่าง:**
องค์กรติดตั้ง IPS ไว้ด้านหน้าระบบฐานข้อมูล หากพบทราฟฟิกที่มี signature คล้าย SQL Injection เช่น `"UNION SELECT"` ในคำสั่ง HTTP request ระบบจะบล็อกแพ็กเก็ตทันทีและตัดการเชื่อมต่อจากผู้โจมตี ก่อนที่เซิร์ฟเวอร์จะได้รับคำสั่งนั้น การตอบสนองระดับนี้ช่วยลดโอกาสที่แฮกเกอร์จะเข้าถึงข้อมูลหรือฝัง malicious code ลงในระบบ



## ✅ วิธีตรวจจับของ IPS

### 1) **Signature-based Detection**

เป็นวิธีตรวจจับโดยอาศัยฐานข้อมูล *signature* ของภัยคุกคามที่เคยเกิดขึ้นแล้ว เช่น hash, pattern ของ payload หรือรูปแบบ packet ที่ผิดปกติ หลักการคือเปรียบเทียบทราฟฟิกที่ผ่านระบบกับฐานข้อมูลดังกล่าว หากตรงกันจะถือว่าเป็นภัยและบล็อกทันที วิธีนี้มีประสิทธิภาพสูงและแม่นยำต่อภัยที่รู้จักอยู่แล้ว แต่ไม่สามารถป้องกันการโจมตีแบบ zero-day ที่ไม่มี signature ในฐานข้อมูลได้ ตัวอย่าง เช่น ตรวจจับ exploit ของ EternalBlue หรือโค้ด SQL Injection ที่นิยมใช้

### 2) **Anomaly-based Detection**

ใช้โมเดลพฤติกรรมปกติของระบบ (*baseline behavioral model*) และวิเคราะห์ทราฟฟิกเพื่อหาความเบี่ยงเบน เช่น ปริมาณ request เพิ่มผิดปกติ การเปิด session จำนวนมากในเวลาอันสั้น เหมาะสำหรับตรวจจับการโจมตีรูปแบบใหม่หรือไม่เคยพบมาก่อน อย่างไรก็ตาม อาจเกิด false positive ได้สูงหาก baseline ไม่แม่นยำ

### 3) **Behavior-based Detection**

มุ่งตรวจสอบ *พฤติกรรมเชิงตรรกะ* ที่ชี้ว่าระบบอาจถูกโจมตี เช่น พยายาม brute-force login, การรันคำสั่งต้องห้าม หรือเปลี่ยนค่าคอนฟิกผิดปกติ ระบบจะปิดกั้นกิจกรรมทันทีแม้ไม่รู้จักมัลแวร์หรือ exploit รูปแบบนั้นมาก่อน เหมาะในระบบ Zero-Trust และ environment ที่มี critical assets เช่น banking และ healthcare

### 4) **Heuristic-based Detection**

ประเมินความเป็นไปได้เชิงตรรกะว่าเหตุการณ์ใดเป็นภัย โดยใช้ rule และ machine learning บางส่วน เช่น การตรวจโค้ด JavaScript ที่มีลักษณะ obfuscation หรือพยายามเชื่อมต่อ C2 server วิธีนี้เป็นการประสาน signature + behavior ช่วยเพิ่มความสามารถในการตรวจจับภัยใหม่

## 3.7 ตัวกรองเนื้อหาและป๊อปอัปบล็อกเกอร์

### ✅ **ตัวกรองเนื้อหา (Content Filtering)**

ตัวกรองเนื้อหาเป็นกลไกควบคุมการเข้าถึงข้อมูลบนอินเทอร์เน็ตตามนโยบายด้านความปลอดภัยขององค์กร โดยอาศัยหลักการ *policy-based access control* และ *URL/MIME filtering* เพื่อจำกัดเว็บไซต์หรือไฟล์ที่มีความเสี่ยง เช่น เว็บไซต์ฟิชชิง เนื้อหาที่ละเมิดลิขสิทธิ์ หรือไฟล์ปฏิบัติการต้องสงสัย ตัวกรองเหล่านี้อาจทำงานบน proxy, firewall หรือ cloud-based security gateway ทฤษฎีที่เกี่ยวข้องคือการลด *attack surface* และใช้แนวคิด *least privilege* เพื่อให้ผู้ใช้เข้าถึงเฉพาะทรัพยากรที่จำเป็น ตัวอย่างการใช้งาน เช่น โรงเรียนตั้งค่า secure web gateway ให้บล็อกเว็บไซต์การพนันและสื่อลามก หรือองค์กรธุรกิจบล็อกเว็บไซต์แชร์ไฟล์ที่อาจเป็นแหล่งกระจาย ransomware นอกจากนี้ ระบบอาจสแกนไฟล์ดาวน์โหลดผ่าน **antimalware sandboxing** ก่อนอนุญาตเข้าเครือข่าย เพื่อป้องกันมัลแวร์แบบ zero-day



### ✅ **ป๊อปอัปบล็อกเกอร์ (Pop-up Blockers)**

ป๊อปอัปบล็อกเกอร์เป็นมาตรการบนเว็บเบราว์เซอร์ที่ออกแบบเพื่อหยุดการแสดงหน้าต่างหรือแท็บโฆษณาที่ถูกเรียกเปิดโดยสคริปต์ JavaScript หรือกลไกฝั่งลูกข่ายอื่นๆ หลักคิดสำคัญคือการป้องกัน *drive-by downloads* และ *malicious JavaScript injection* ซึ่งเป็นเทคนิคที่แฮกเกอร์ใช้แพร่มัลแวร์ ฟิชชิง หรือหลอกให้ผู้ใช้คลิกอัปเดตปลอม ตัวบล็อกเกอร์จะตรวจสอบ event-trigger เช่น `window.open()` หรือ script-spawned pop-ups และบล็อกก่อนหน้าต่างถูกเรนเดอร์ ตัวอย่าง เช่น ผู้ใช้เยี่ยมชมเว็บไซต์ที่แอบฝังโฆษณาหลอกให้ติดตั้ง “antivirus ฟรี” เมื่อบล็อกเกอร์ทำงาน หน้าต่างลวงเหล่านั้นจะไม่แสดง ทำให้ลดโอกาสที่ผู้ใช้ติดมัลแวร์ประเภท adware หรือ banking trojan นอกจากนี้ ระบบความปลอดภัยบนเบราว์เซอร์สมัยใหม่ยังรวม **anti-tracking** เพื่อหยุด third-party scripts ที่เก็บคุกกี้หรือติดตามพฤติกรรมผู้ใช้



### ✅ **การอัปเดตเบราว์เซอร์และส่วนขยายสม่ำเสมอ**

การอัปเดตเบราว์เซอร์และส่วนขยายเป็นแนวทางพื้นฐานใน cybersecurity ที่อิงตามหลัก *secure software lifecycle* และ *patch management* ช่องโหว่ในเบราว์เซอร์หรือปลั๊กอิน เช่น Adobe Flash, JavaScript engine หรือ extension อาจถูกใช้ทำ **remote code execution (RCE)** หรือ **privilege escalation** ทำให้แฮกเกอร์สามารถติดตั้งมัลแวร์หรือเข้าถึงข้อมูลผู้ใช้ได้ ตัวอย่างกรณีจริง เช่น ช่องโหว่ Zero-day ใน Chrome (CVE-2023-2033) ที่ Google แจ้งเตือนให้ผู้ใช้เร่งอัปเดตเพื่อป้องกันมัลแวร์ใช้ประโยชน์ การอัปเดตสม่ำเสมอช่วยให้เบราว์เซอร์รับฟีเจอร์ด้านความปลอดภัยล่าสุด เช่น site isolation, sandboxing, certificate pinning และตรวจจับ phishing อัตโนมัติ ส่วนองค์กรสามารถใช้ระบบ centralized update เช่น Microsoft Intune หรือ MDM บน macOS เพื่อควบคุมเวอร์ชันและลดความเสี่ยง Zero-day ในระดับองค์กร


ด้านล่างเป็น **ตารางสรุปหลักการ Content Filtering พร้อมตัวอย่างอุปกรณ์/โซลูชัน** จัดรูปแบบให้เหมาะสำหรับหนังสือวิชาการหรือสไลด์สอน

| **DNS Filtering / DNS Security**         | ป้องกันการเข้าถึงโดเมนอันตรายผ่าน DNS resolution block ใช้ threat intel และ behavior-based analysis                | Malware C2 servers, Fake domains, DNS tunneling         | Cisco Umbrella DNS, Cloudflare Gateway, Quad9 Secure DNS, NextDNS                    |
| **Proxy Content Filtering**              | ตรวจสอบ HTTP/HTTPS ผ่าน proxy server วิเคราะห์ request และ response และควบคุมประเภทข้อมูลที่อนุญาต                 | Malicious web content, Data exfiltration via HTTP       | Squid Proxy, Blue Coat ProxySG, pfSense proxy                                        |
| **Email/Web Content Scanning**           | ตรวจสอบไฟล์, สคริปต์, ลิงก์, และ payload ก่อนส่งถึงผู้ใช้                                                          | Phishing emails, Malicious attachments, Macro malware   | Microsoft Defender EOP, Proofpoint TAP, Google Workspace Security                    |
| **Browser-based Filtering / Extensions** | กรองเนื้อหาบนเบราว์เซอร์โดยตรง เช่น block scripts, ads, tracker                                                    | Malicious ads, Pop-ups, Crypto-mining scripts           | uBlock Origin, NoScript, Google Safe Browsing, MS Edge SmartScreen                   |


## 3.8 การป้องกันข้อมูลรั่วไหล (DLP)

### ✅ **Endpoint DLP**

Endpoint DLP เป็นระบบควบคุมข้อมูลที่ทำงานบนอุปกรณ์ปลายทาง เช่น คอมพิวเตอร์ โน้ตบุ๊ก หรือเครื่องพนักงาน จุดเน้นคือการป้องกันข้อมูลรั่วไหลจากการกระทำของผู้ใช้ ไม่ว่าจะตั้งใจหรือไม่ตั้งใจ หลักคิดเชิงทฤษฎีคือการตรวจสอบและควบคุมการกระทำที่เกี่ยวข้องกับไฟล์ เช่น การคัดลอกไฟล์ลง USB drive การสั่งพิมพ์เอกสาร การแนบไฟล์ไปยังอีเมล หรือการอัปโหลดข้อมูลไปยังเว็บไซต์ ระบบจะใช้ทั้ง **content inspection**, **contextual analysis**, และ **behavior monitoring** เพื่อตรวจจับการละเมิดนโยบาย ตัวอย่าง เช่น ระบบแจ้งเตือนเมื่อผู้ใช้พยายามบันทึกไฟล์ Excel ที่มีข้อมูลลูกค้าลง Flash Drive หรือบล็อกการอัปโหลดเอกสารสัญญาไปยังบริการ cloud ส่วนตัว เช่น Google Drive ส่วนบุคคลของผู้ใช้


### ✅ **Network DLP**

Network DLP ทำงานที่ระดับเครือข่ายโดยตรวจสอบข้อมูลที่เคลื่อนที่ออกจากองค์กรผ่านช่องทางการสื่อสารต่าง ๆ เช่น HTTP/HTTPS, SMTP, FTP และช่องทาง VPN ทฤษฎีสำคัญคือ *data-in-motion protection* โดยใช้เทคนิค deep packet inspection (DPI) และ pattern matching เพื่อตรวจจับข้อมูลอ่อนไหว เช่น หมายเลขบัตรเครดิตหรือข้อมูลส่วนบุคคล (PII) เมื่อพบพฤติกรรมผิดปกติ เช่น การส่งไฟล์ฐานข้อมูลผ่านอีเมล ระบบสามารถบล็อกหรือแจ้งเตือนได้ ตัวอย่าง เช่น แผนก SOC พบว่ามีพนักงานพยายามส่งไฟล์ CSV ที่มีข้อมูลพนักงานออกไปทางอีเมลส่วนตัว ระบบ Network DLP จะบล็อกการส่ง และแจ้งเตือนฝ่ายความปลอดภัยทันที


### ✅ **Storage DLP**

Storage DLP มุ่งเน้นปกป้อง *data-at-rest* ภายในระบบฐานข้อมูล ศูนย์ข้อมูล และ file server โดยมีกระบวนการตรวจสอบ สแกน และจำแนกข้อมูลที่จัดเก็บอย่างต่อเนื่อง หลักคิดคือการทำ *data discovery and classification* เพื่อระบุข้อมูลสำคัญ เช่น เอกสารลับ สัญญาธุรกิจ ข้อมูลสุขภาพ (PHI) หรือเอกสารด้านการบัญชี และป้องกันการเข้าถึงหรือคัดลอกโดยไม่ได้รับอนุญาต ตัวอย่าง เช่น ระบบ DLP ทำการสแกน NAS ในองค์กรและพบว่ามีไฟล์ที่มีข้อมูลบัตรประชาชนถูกเก็บในโฟลเดอร์ที่ไม่ได้เข้ารหัสและเปิดสิทธิ์ให้ทุกคนเข้าถึง จึงแจ้งเตือนฝ่าย IT ให้ย้ายข้อมูลและปรับสิทธิ์การเข้าถึงตามมาตรฐานความปลอดภัย


### ✅ **Cloud DLP**

Cloud DLP ใช้สำหรับป้องกันข้อมูลในระบบคลาวด์ เช่น SaaS, PaaS และ IaaS ซึ่งเป็นส่วนสำคัญในยุคที่องค์กรใช้บริการอย่าง Microsoft 365, Google Workspace หรือ Salesforce หลักคิดคือการควบคุม *data governance in cloud environments* และป้องกันการแชร์ข้อมูลผิดที่หรือเปิดสิทธิ์เกินจำเป็น เช่น public access ตัวอย่างเชิงทฤษฎีคือการใช้ API หรือ agent เพื่อตรวจสอบไฟล์บนบริการ cloud storage และบังคับใช้ policy เช่น block public sharing หรือแจ้งเตือนเมื่อข้อมูลสำคัญถูกอัปโหลดขึ้น cloud ส่วนบุคคล ตัวอย่าง: พนักงานอัปโหลดไฟล์ลูกค้าไปยัง Google Drive ของตนเองเพื่อทำงานที่บ้าน ระบบ Cloud DLP ของ Microsoft Purview จะบล็อกการอัปโหลดและแจ้งเตือนผู้ดูแลระบบ


## 3.9 ความปลอดภัย BIOS/UEFI


### ✅ 1) อัปเดตเฟิร์มแวร์ให้เป็นเวอร์ชันล่าสุด

การอัปเดตเฟิร์มแวร์ BIOS/UEFI เป็นมาตรการที่สำคัญในการลดช่องโหว่ระดับระบบก่อนบูต ตามหลักการ *Secure Firmware Lifecycle Management* อัปเดตเฟิร์มแวร์ช่วยแก้ไขช่องโหว่ที่อาจถูกใช้โจมตี เช่น การแทรก rootkit หรือการ bypass ระบบยืนยันตัวตน ฟิร์มแวร์ระดับต่ำเป็นพื้นฐานของโครงสร้างความปลอดภัยทั้งหมด หากถูกเจาะสำเร็จ ผู้โจมตีอาจควบคุมระบบได้ก่อนที่ระบบปฏิบัติการจะโหลด ตัวอย่างเช่น ช่องโหว่ “ThinkPwn” ที่เคยทำให้แล็ปท็อป Lenovo หลายรุ่นถูกโจมตีโดยปรับแต่ง firmware interface เพื่อนำสิทธิ์สูงสุด (privilege escalation) การอัปเดต BIOS/UEFI จึงเป็นขั้นตอนสำคัญเพื่อป้องกันภัยคุกคามระดับ firmware


### ✅ 2) ตั้งรหัสผ่าน BIOS

การตั้งรหัสผ่าน BIOS หรือ *firmware password* เป็นแนวปฏิบัติเพื่อป้องกันไม่ให้บุคคลที่ไม่ได้รับอนุญาตเข้ามาเปลี่ยนค่าการตั้งค่าระดับระบบ เช่น ลำดับการบูตหรือระบบความปลอดภัยฮาร์ดแวร์ หลักคิดนี้สอดคล้องกับการควบคุมแบบ *Access Control* และแนวคิด *Zero Trust* ในระดับเฟิร์มแวร์ ตัวอย่างเช่น หากผู้โจมตีเข้าถึงเครื่องได้โดยตรง เขาอาจเข้า BIOS และปิด Secure Boot หรือเปิดการบูตจาก USB เพื่อรัน Linux Live เพื่อละเมิดระบบรหัสผ่านของ OS การตั้งรหัสผ่าน BIOS จะยับยั้งความพยายามดังกล่าวโดยบังคับให้มีการตรวจสอบตัวตนก่อน


### ✅ 3) ปิดการบูตจาก USB/CD

การปิดการบูตจาก USB หรือ CD/DVD เป็นมาตรการป้องกันการโจมตีรูปแบบ *evil maid attack* หรือการเข้าถึงเครื่องโดยตรงเพื่อโหลด OS ภายนอกและเข้าถึงข้อมูลหรือ bypass ระบบยืนยันตัวตน หลักคิดคือบังคับให้ระบบบูตจาก storage ที่ได้รับความเชื่อถือเท่านั้น ลดความเสี่ยงจากสื่อบูตที่มี payload อันตราย เช่น bootkit หรือ forensic toolkit ตัวอย่าง เช่น ผู้โจมตีใช้ USB Kali Linux เพื่อบูตเครื่องพนักงานแล้วดึงข้อมูล credential ผ่าน memory forensic หากระบบตั้งค่าปิดการบูต USB การโจมตีลักษณะนี้จะถูกป้องกันได้อย่างมีประสิทธิภาพ


### ✅ 4) ปิดพอร์ตและอุปกรณ์ที่ไม่จำเป็น

เป็นการประยุกต์ใช้หลัก *least functionality* และ *attack surface reduction* โดยปิดใช้งานพอร์ตหรืออุปกรณ์ที่ไม่จำเป็น เช่น Thunderbolt, FireWire, หรือ hardware virtualization module ที่ไม่ได้ใช้งาน การปิดฟีเจอร์ที่ไม่จำเป็นช่วยลดโอกาสให้ผู้โจมตีใช้ interface เหล่านั้นในการแพร่มัลแวร์ ทำ DMA attack หรือ bypass ระบบรักษาความปลอดภัย ตัวอย่างเช่น การโจมตีผ่าน Thunderbolt (Thunderclap attack) ที่สามารถเข้าถึง memory โดยตรงบนแล็ปท็อปที่ไม่ได้ปิดพอร์ตนี้ใน BIOS การปิดพอร์ตดังกล่าวจึงช่วยลดความเสี่ยงได้อย่างมาก


### ✅ 5) เปิดใช้งาน Secure Boot

Secure Boot เป็นฟีเจอร์ของ UEFI ที่ตรวจสอบความถูกต้องของ bootloader และระบบปฏิบัติการด้วย *cryptographic signatures* ก่อนอนุญาตให้บูต กระบวนการนี้ป้องกันมัลแวร์ประเภท bootkit และ rootkit ที่พยายามรันก่อน OS เช่น MBR/VBR malware หลักคิดคือการสร้าง *trusted computing base (TCB)* ตั้งแต่เริ่มต้น เมื่อเปิดใช้ Secure Boot เฉพาะซอฟต์แวร์ที่มี digital signature ถูกต้องตาม trust store ของระบบเท่านั้นที่สามารถรันได้ ตัวอย่างเช่น มัลแวร์ BlackLotus ที่โจมตี Secure Boot บน Windows โดยใช้ช่องโหว่เก่า ผู้ดูแลต้องอัปเดต patch และ revoke certificate เก่าเพื่อให้ Secure Boot ยังคงป้องกันได้อย่างมีประสิทธิภาพ


ด้านล่างเป็นสรุปในรูปแบบ **ตารางเปรียบเทียบ BIOS vs UEFI Security Controls** และ **ผัง Zero-Trust Boot Architecture** เพื่อประกอบเนื้อหาเชิงวิชาการในบทเรียน

## ✅ ตารางเปรียบเทียบ BIOS vs UEFI Security Controls

| หมวด                      | BIOS                                                      | UEFI                                                            |
| ------------------------- | --------------------------------------------------------- | --------------------------------------------------------------- |
| สถาปัตยกรรม               | ระบบเฟิร์มแวร์แบบเดิม ใช้งาน interrupt call และ real-mode | ระบบเฟิร์มแวร์สมัยใหม่ รองรับ protected mode และ driver model   |
| ความปลอดภัยพื้นฐาน        | รหัสผ่าน BIOS เพื่อป้องกันการแก้ไขการตั้งค่า              | รหัสผ่าน UEFI, ระบบการตรวจสอบสิทธิ์แบบแข็งแกร่งกว่า             |
| การป้องกันบูต             | ไม่มีระบบตรวจสอบความถูกต้องของ bootloader                 | **Secure Boot** ตรวจสอบ digital signature ของ bootloader และ OS |
| การจัดการ                 | ใช้คีย์บอร์ดเท่านั้น UI แบบพื้นฐาน                        | เมนูกราฟิก รองรับเมาส์, การจัดการ policy ละเอียดกว่า            |
| ความสามารถด้าน Encryption | ไม่มี native support                                      | รองรับ TPM สำหรับ key storage และฟีเจอร์ crypto อื่นๆ           |
| ความต้านทาน rootkit       | เสี่ยงต่อ BIOS rootkit สูง                                | ป้องกัน bootkit/rootkit ได้ดีกว่า ผ่าน cryptographic validation |
| ความเหมาะสม               | ระบบเก่า, hardware legacy                                 | อุปกรณ์องค์กรสมัยใหม่, Cloud-PC, virtualization environment     |

**สรุป:**
UEFI มีโครงสร้างความปลอดภัยเชิงลึกกว่า รองรับมาตรการเข้ารหัสและตรวจสอบ digital signature ทำให้เหมาะกับ Zero-Trust architecture ในระบบองค์กรสมัยใหม่


## ✅ ผัง Zero-Trust Boot Architecture

ด้านล่างเป็นผัง conceptual ที่ใช้ประกอบหนังสือหรือสไลด์

```
            ┌─────────────────────────┐
            │   Hardware Root of Trust│
            │  (TPM / Firmware keys)  │
            └───────────┬────────────┘
                        ↓
             ┌────────────────────────┐
             │   UEFI Secure Boot     │
             │ Validate bootloader    │
             │ via signed certificates│
             └───────────┬───────────┘
                         ↓
       ┌──────────────────────────────────┐
       │     Trusted Boot Loader          │
       │ Verified against allowed keys    │
       └───────────┬─────────────────────┘
                   ↓
     ┌────────────────────────────────────┐
     │ OS Kernel Integrity Check          │
     │ Secure kernel + driver validation │
     └───────────┬──────────────────────┘
                 ↓
  ┌────────────────────────────────────────┐
  │  Endpoint Security / EDR Activation    │
  │ Memory integrity, runtime protection   │
  └────────────────────────────────────────┘

Zero-Trust Principle:
"Never trust the boot process unless cryptographically verified."
```

### 💡 จุดเน้นสำคัญในผัง Zero-Trust Boot

* ใช้ **Hardware-Rooted Trust** (เช่น TPM)
* Bootloader และ Kernel ต้องได้รับการ **sign & verify**
* ระบบ endpoint protection ทำงานตั้งแต่ต้น
* Boot ที่ไม่ผ่านการตรวจสอบถูก **ปฏิเสธทันที**


## 3.10 การป้องกันอุปกรณ์จัดเก็บข้อมูล

### ✅ **เข้ารหัสข้อมูล**

การเข้ารหัสข้อมูลสำหรับอุปกรณ์จัดเก็บข้อมูลเป็นมาตรการสำคัญเพื่อรักษาความลับของข้อมูล (*confidentiality*) ตามกรอบ **CIA Triad** หลักการคือแปลงข้อมูลให้อยู่ในรูปแบบที่ไม่สามารถอ่านได้โดยไม่ใช้กุญแจถอดรหัส วิธีนี้ช่วยลดความเสี่ยงจากการสูญหายและการขโมยอุปกรณ์ ซึ่งถือเป็นภัยคุกคามด้าน physical security ตัวอย่างเทคโนโลยีที่ใช้ ได้แก่ Full Disk Encryption (เช่น BitLocker, FileVault) และ Self-Encrypting Drive (SED) การเข้ารหัสมีประโยชน์โดยเฉพาะในกรณีแล็ปท็อปพกพา หรือ storage ภายนอกที่เสี่ยงต่อการสูญหาย เช่น USB drive หากอุปกรณ์ถูกขโมยหรือสูญหาย ผู้ไม่หวังดีจะไม่สามารถเข้าถึงข้อมูลได้ แม้จะนำฮาร์ดดิสก์ไปเชื่อมต่อกับเครื่องอื่นก็ตาม


### ✅ **ควบคุมสิทธิ์เข้าถึงและบันทึกการใช้งาน**

การควบคุมสิทธิ์เข้าถึงข้อมูล (*Access Control*) เป็นหลักการความปลอดภัยที่เน้นแนวคิด **Least Privilege** ให้ผู้ใช้เข้าถึงเฉพาะข้อมูลที่จำเป็นต่อหน้าที่ พร้อมทั้งมีระบบตรวจสอบและบันทึกการใช้งาน (*audit logging*) เพื่อให้สามารถวิเคราะห์เหตุการณ์ย้อนหลังได้ ระบบอาจใช้เทคโนโลยี เช่น Role-Based Access Control (RBAC) หรือ Multi-Factor Authentication (MFA) เพื่อยกระดับความปลอดภัย ตัวอย่าง เช่น องค์กรกำหนดให้เฉพาะทีมบัญชีเข้าถึงไฟล์ทางการเงินบน NAS และระบบบันทึกการเข้าถึงทุกครั้งไว้ใน SIEM หากมีพนักงานที่ไม่ได้รับอนุญาตพยายามเปิดไฟล์ ระบบจะแจ้งเตือนและบันทึกเพื่อวิเคราะห์เหตุการณ์ความปลอดภัย


### ✅ **ทำลายสื่อที่เลิกใช้อย่างปลอดภัย**

การทำลายสื่อจัดเก็บข้อมูลที่เลิกใช้อย่างปลอดภัยเป็นส่วนหนึ่งของ **data sanitization** และสอดคล้องกับมาตรฐาน NIST SP 800-88 เพื่อป้องกันการกู้คืนข้อมูลสำคัญจากอุปกรณ์เก่า วิธีการประกอบด้วยการลบข้อมูลอย่างปลอดภัยด้วยเครื่องมือ overwrite ซ้ำหลายรอบ (*secure wiping*) หรือทำลายทางกายภาพ เช่น การบดทุบ การเผา หรือการตัดแผ่นดิสก์ ตัวอย่างเช่น องค์กรด้านสาธารณสุขที่ต้องปฏิบัติตามกฎหมายข้อมูลส่วนบุคคล PDPA จะทำลาย SSD ที่หมดอายุใช้งานด้วยวิธี shredder ตามมาตรฐานความปลอดภัย เพื่อป้องกันข้อมูลผู้ป่วยรั่วไหลซึ่งอาจก่อให้เกิดความเสียหายทางกฎหมายและชื่อเสียงองค์กร



### ✅ ตารางเปรียบเทียบและการเลือกวิธีทำลายสื่อจัดเก็บข้อมูล

| ------------------------------ | ----------------------------------------- | ------------------------------------- | ---------------------------------- | ------------------------------------------ | ------------------------------------------------------ |
| **Secure Wipe (Overwrite)**    | เขียนข้อมูลใหม่ทับหลายรอบจนกู้คืนไม่ได้   | HDD, USB Flash Drive (บางประเภท)      | ไม่ต้องทำลายอุปกรณ์, ค่าใช้จ่ายต่ำ | ใช้เวลานาน, ไม่ได้ผลกับ SSD เสมอไป         | องค์กรที่ต้อง reuse HDD ก่อนแจกจ่ายให้พนักงานใหม่      |

### 🧠 แนวทางเลือกใช้งานตามความเสี่ยง

* **ข้อมูลทั่วไปภายในองค์กร** → Secure Wipe พอเพียง
* **ข้อมูลสำคัญระดับธุรกิจ/สัญญา** → Wipe แล้ว Shred

## การเข้ารหัสข้อมูล

### **Full Disk Encryption (FDE)** – BitLocker, FileVault

Full Disk Encryption เป็นแนวคิดเข้ารหัสข้อมูลทั้งดิสก์โดยอัตโนมัติ เพื่อให้ข้อมูลทั้งหมดบนระบบเก็บอยู่ในสภาวะเข้ารหัสตั้งแต่บูตเครื่องจนถึงปิดระบบ หลักการนี้ยึดแนวคิด *data-at-rest protection* และลดความเสี่ยงจากการเข้าถึงข้อมูลแบบ physical attack เช่น การถอดดิสก์เพื่อนำไปอ่านบนอีกเครื่อง ตัวอย่างเช่น BitLocker บน Windows ใช้ TPM เพื่อจัดการกุญแจและเปิดใช้โหมด Secure Boot เพื่อยืนยันความถูกต้องของระบบก่อนปลดล็อกดิสก์ ส่วน FileVault บน macOS ใช้ภาษาเข้ารหัส AES-256 และตรวจสอบสิทธิ์ผู้ใช้ก่อนถอดรหัสดิสก์ ทำให้ผู้โจมตีไม่สามารถสกัดข้อมูลได้ แม้จะมีสิทธิ์ทางกายภาพกับอุปกรณ์ก็ตาม


### **Self-Encrypting Drives (SED)**

SED คืออุปกรณ์จัดเก็บข้อมูลที่มีโมดูลเข้ารหัสในตัวฮาร์ดแวร์ ทำให้การเข้ารหัสและถอดรหัสทำงานที่ระดับคอนโทรลเลอร์โดยตรง แนวคิดนี้สอดคล้องกับ *hardware-rooted security* และมีข้อได้เปรียบด้านประสิทธิภาพเพราะไม่พึ่งหน่วยประมวลผลของระบบ สอดคล้องกับมาตรฐาน IEEE 1667 และ TCG Opal ตัวอย่าง: SSD ในองค์กรที่เรียกใช้ SED สามารถป้องกันข้อมูลแม้อุปกรณ์ถูกขโมย และเมื่อดำเนินกระบวนการ secure disposal อาจเพียงเปลี่ยน key ภายใน ทำให้ข้อมูลทั้งหมดไม่สามารถเข้าถึงได้ทันที (crypto-erase)



### **TPM (Trusted Platform Module)**

TPM คือชิปความปลอดภัยที่ติดตั้งบนเมนบอร์ดเพื่อเก็บกุญแจเข้ารหัสและข้อมูลยืนยันตัวตนอย่างปลอดภัย หลักการสำคัญคือ *hardware trust anchor* ซึ่งเป็นรากฐานให้ระบบเชื่อถือสถานะก่อนเริ่มบูต เช่น ตรวจสอบ integrity ของ bootloader ก่อนปลดกุญแจ BitLocker การใช้ TPM ทำให้ลดความเสี่ยงจาก key extraction ผ่าน memory attacks หรือ disk cloning ตัวอย่างเช่น ในองค์กร ใช้ TPM ป้องกันไม่ให้ผู้โจมตีคัดลอกดิสก์ของเครื่องและ boot จากอีกอุปกรณ์เพื่อข้ามระบบยืนยันตัวตน



### **HSM (Hardware Security Module)**

HSM เป็นโมดูลฮาร์ดแวร์เฉพาะที่ออกแบบมาสำหรับเก็บและประมวลผลกุญแจเข้ารหัสระดับองค์กร ใช้หลักการ *key isolation* และ *tamper-resistant architecture* เหมาะกับบริการที่ต้องการความปลอดภัยสูง เช่น PKI, บริการธนาคาร หรือระบบออกใบรับรองดิจิทัล HSM ช่วยสร้างกุญแจ เก็บกุญแจ และดำเนินงานเข้ารหัสโดยไม่เปิดเผยกุญแจออกภายนอก ตัวอย่างเช่น องค์กรการเงินใช้ HSM เพื่อปกป้อง private key ในระบบชำระเงินการ์ด (PCI-DSS compliance)



### **AES (Symmetric Encryption) และ RSA/ECC (Asymmetric Encryption)**

AES เป็นมาตรฐานการเข้ารหัสสมมาตรที่ได้รับเลือกโดย NIST ใช้ key เดียวในการเข้ารหัสและถอดรหัส มีประสิทธิภาพสูงและนิยมใช้ใน FDE, VPN และ IPSec ส่วน RSA และ ECC เป็นระบบกุญแจคู่ใช้ public-private key model เพื่อถอดรหัสหรือสร้าง digital signature ลูกค้าองค์กรใช้ RSA/ECC ใน TLS, PKI และระบบยืนยันตนแบบ certificate-based ตัวอย่างเช่น VPN ใช้ RSA/ECC เพื่อแลกกุญแจ และใช้ AES ในการเข้ารหัสทราฟฟิกจริงตามหลัก hybrid encryption model


## สรุป


บทสรุปนี้สังเคราะห์สาระสำคัญในบทว่าด้วยระบบประยุกต์และอุปกรณ์ด้านความมั่นคงปลอดภัยเพื่อสร้างกรอบความเข้าใจที่เป็นระบบและเชื่อมโยงเชิงสถาปัตยกรรมความปลอดภัยสมัยใหม่ ภาพรวมสำคัญคือแนวคิด Defense in Depth ซึ่งเน้นการวางมาตรการหลายชั้นตั้งแต่ระดับโฮสต์ เครือข่าย จนถึงข้อมูล เป้าหมายคือให้กลไกด้านการตรวจจับ ป้องกัน และตอบสนองสนับสนุนกันเพื่อลดโอกาสการละเมิดแม้ชั้นใดชั้นหนึ่งถูกโจมตี ในระดับอุปกรณ์ปลายทาง เครื่องมืออย่างไฟร์วอลล์แบบซอฟต์แวร์ ระบบป้องกันมัลแวร์ และเทคโนโลยี EDR ทำหน้าที่สร้างขอบป้องกันเชิงพฤติกรรมและลดช่องโจมตีภายในเครื่อง ขณะที่ระดับเครือข่ายอาศัยไฟร์วอลล์ ระบบ IDS/IPS และ content filtering เพื่อควบคุมและตรวจสอบการสื่อสารปริมาณมหาศาลในสภาพแวดล้อมที่ซับซ้อน

ในระดับข้อมูล องค์กรบังคับใช้การเข้ารหัส กระบวนการควบคุมสิทธิ์ และการจัดหมวดหมู่ข้อมูลควบคู่กับระบบ DLP สำหรับตรวจจับและป้องกันการรั่วไหล กลไกเหล่านี้เสริมด้วยมาตรการการทำลายสื่ออย่างปลอดภัยตามมาตรฐาน เช่น NIST SP 800-88 เพื่อป้องกันการกู้คืนข้อมูลจากอุปกรณ์ที่หมดอายุใช้งาน ด้านโครงสร้างความเชื่อถือของระบบ บทนี้อธิบายความปลอดภัย BIOS/UEFI รวมถึงการยืนยันความถูกต้องระหว่างกระบวนการบูตผ่าน Secure Boot และการใช้ส่วนประกอบฮาร์ดแวร์ที่สร้างรากความเชื่อถือ เช่น TPM และ HSM ทั้งหมดนี้สะท้อนกรอบ Zero-Trust ซึ่งไม่เชื่อถือผู้ใช้หรือซอฟต์แวร์โดยอัตโนมัติแต่ต้องตรวจสอบอย่างเป็นระบบ

กล่าวโดยสรุป บทนี้ย้ำว่าความมั่นคงปลอดภัยขององค์กรไม่ได้อาศัยเพียงผลิตภัณฑ์หนึ่งชิ้น แต่เกิดจากการบูรณาการเครื่องมือและมาตรการหลายมิติ ทั้งเทคนิค กระบวนการ และการกำกับดูแล เมื่อรวมกันแล้วจึงสามารถลดความเสี่ยงจากภัยคุกคามที่พัฒนาอย่างต่อเนื่องและสร้างสภาพแวดล้อมสารสนเทศที่มีความทนทานเชิงความมั่นคงปลอดภัยสูงสำหรับองค์กรยุคดิจิทัล
