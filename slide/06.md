## 1. LAN Security Overview

**LAN (Local Area Network):**  
An internal network interconnecting computers, switches, and routers.

**Security Goal:**  
Ensure **confidentiality, integrity, and availability** at Layer 2.

**Common Risks:**
- Unauthorized access  
- Internal spoofing  
- Traffic interception  
- Rogue DHCP or ARP poisoning  
- VLAN hopping  

---

## 2. LAN Attack Vectors

| Attack Type | Description | Goal |
|--------------|--------------|------|
| **MAC Flooding** | Fills switch CAM table with fake MACs | Force switch to broadcast traffic |
| **DHCP Spoofing** | Fake DHCP server assigns wrong gateway/DNS | Redirect or block user traffic |
| **ARP Spoofing** | Sends fake ARP replies to impersonate gateway | Enable MITM/sniffing |
| **VLAN Hopping** | Exploits trunk misconfiguration | Access unauthorized VLANs |

---

## 3. Effect on Network Protocols

| Protocol | Weakness | Exploit Impact |
|-----------|------------|----------------|
| **ARP** | No authentication | MITM via spoofed ARP replies |
| **DHCP** | No server validation | Rogue DHCP server poisoning |
| **STP** | Default trust of root bridge | Force topology change |
| **802.1Q (VLAN)** | Mis-tagging possible | Unauthorized VLAN access |
| **ICMP** | No session control | Network reconnaissance |

### (A) MAC Flooding Attack

**Concept:**  
Attacker floods switch with thousands of fake MAC addresses.

**Effect:**  
Switch CAM table overflows → broadcasts all frames → attacker can sniff all traffic.

**Simulate in Packet Tracer:**
- Configure PC1 as attacker.
- Send multiple fake source MACs using simulation mode.
- Observe switch flooding packets to all ports.

---

### (A) MAC Flooding Attack

**Detection:**
```bash
show mac address-table
````

– Many unknown MACs from one port = suspicious.

**Prevention:**

```bash
interface fa0/2
 switchport port-security
 switchport port-security maximum 2
 switchport port-security violation shutdown
```

---

### (B) DHCP Spoofing Attack

**Concept:**
Attacker runs a fake DHCP service assigning wrong gateway/DNS.

**Effect:**
Victim receives malicious network configuration → traffic redirected or blocked.

**Simulate:**

* Configure PC1 as DHCP server.
* Server assigns wrong gateway (e.g., 192.168.1.254).

---

### (B) DHCP Spoofing Attack


**Detection:**

```bash
show ip dhcp binding
```

– Incorrect gateway or DNS for clients.

**Prevention:**

```bash
ip dhcp snooping
ip dhcp snooping vlan 10
interface fa0/24
 ip dhcp snooping trust
```

---

### (C) ARP Spoofing / Poisoning

**Concept:**
Attacker sends fake ARP replies:
“Gateway IP is at Attacker’s MAC.”

**Effect:**
Victim traffic passes through attacker (MITM).

**Simulate:**

* Use PC1 to send ARP replies to PC0 and gateway.
* Observe ARP table on PC0.

---

### (C) ARP Spoofing / Poisoning

**Detection:**
On victim:

```bash
arp -a
```

Gateway MAC differs → spoof detected.

**Prevention:**

```bash
ip dhcp snooping
ip arp inspection vlan 10
interface fa0/24
 ip arp inspection trust
```

---

### (D) VLAN Hopping

**Concept:**
Attacker crafts packets with double VLAN tags to access another VLAN.

**Effect:**
Cross-VLAN packet leakage (data exfiltration or sniffing).

**Detection:**

* Unexpected inter-VLAN communication.
* Logs showing unauthorized VLAN IDs.

---

### (D) VLAN Hopping

**Prevention:**

```bash
interface range fa0/1 - 20
 switchport mode access
 switchport access vlan 10
 switchport nonegotiate
```

Disable trunking on access ports.

## 5. Detecting LAN Attacks

**Techniques:**

* Monitor MAC table size and anomalies.
* Compare DHCP bindings and ARP tables.
* Use IDS/IPS for Layer 2 signatures.
* Enable logging and SNMP traps on switches.

**Cisco Verification Commands:**

```bash
show port-security
show ip dhcp snooping binding
show ip arp inspection statistics
show log
```

## 6. Defense: Switch Security Mechanisms

| Feature                    | Protects Against | Key Command                      |
| -------------------------- | ---------------- | -------------------------------- |
| **Port Security**          | MAC Flooding     | `switchport port-security`       |
| **DHCP Snooping**          | DHCP Spoofing    | `ip dhcp snooping`               |
| **Dynamic ARP Inspection** | ARP Spoofing     | `ip arp inspection vlan`         |
| **VLAN Pruning**           | VLAN Hopping     | `switchport mode access`         |
| **BPDU Guard**             | STP Attacks      | `spanning-tree bpduguard enable` |

---

### Configuration Summary

* Rogue DHCP blocked/Spoofed ARP dropped/MAC flooding prevented

```bash
! Enable Layer 2 protections
```

## 8. Troubleshooting

| Symptom                 | Likely Cause        | Resolution                    |
| ----------------------- | ------------------- | ----------------------------- |
| Clients fail to get IP  | Untrusted DHCP port | Trust uplink interface        |
| Port down (err-disable) | Too many MACs       | Increase or clear sticky MACs |
| DHCP blocked            | VLAN not enabled    | Add `ip dhcp snooping vlan`   |
| ARP still spoofed       | DAI off             | Verify ARP inspection active  |

---

## 9. Best Practices

* Enable *port security* on all access ports.
* Use *sticky MAC* for fixed endpoints.
* Trust only uplink and trunk ports.
* Disable unused ports (`shutdown`).
* Monitor logs for violations.
* Combine with NAC/802.1X for enterprise-grade control.
