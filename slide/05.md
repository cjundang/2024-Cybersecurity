## 1. Introduction to Firewalls

**Definition:**  
A firewall is a network security device that monitors and controls incoming and outgoing traffic based on predetermined security rules.

**Purpose:**  
- Enforce network security policies  
- Block unauthorized access  
- Separate trusted and untrusted zones  
- Record and analyze traffic events  

---

## Firewall in Network Security Architecture

```

[Internet]
↓
[Perimeter Firewall]
↓
[DMZ: Web/Email Servers]
↓
[Internal Network]
↓
[Host-Based Firewalls]

```

**Defense-in-Depth Role:**  
Firewalls provide **first-line traffic control**, complemented by IDS/IPS and endpoint security.

---

## 2. Firewall Fundamentals

| Concept | Description | Example |
|----------|--------------|----------|
| **Rule** | Defines which packets are allowed or denied | “Allow TCP 80 from LAN to Internet” |
| **Policy** | Collection of rules applied to interfaces | “Inbound Policy: Deny All Except HTTPS” |
| **Zone** | Logical network segment grouping | Internal, DMZ, External |
| **Default Action** | Behavior when no rule matches | Usually *deny* (implicit deny) |

**Instructor Note:**  
Emphasize policy hierarchy and rule order evaluation (top-down).

---

## Types of Firewalls

| Type | Layer | Description |
|------|--------|-------------|
| **Packet-Filtering** | L3/L4 | Filters based on IP, port, protocol |
| **Stateful Inspection** | L3-L7 | Tracks connection states |
| **Proxy Firewall** | L7 | Mediates traffic through application proxy |
| **Next-Generation (NGFW)** | L7+ | Adds DPI, IDS/IPS, and app awareness |

---

## 3. Packet Inspection

### **Stateless (Packet-Filtering)**
- Examines packets independently  
- Rules based on source/destination IP, port, and protocol  
- Fast but limited context awareness  

**Example Rule:**
```

ALLOW TCP src=192.168.1.0/24 dst=ANY port=80
DENY  ALL

```

**Weakness:**  
Cannot detect abnormal sequence or state.

---

## 4. Stateful Inspection

**Definition:**  
Tracks active sessions using a *state table*, inspecting packet sequences and connection states.

**Advantages:**
- Validates TCP handshakes (SYN → SYN/ACK → ACK)  
- Blocks unsolicited packets  
- More accurate for session-based filtering  

**Example:**  
Firewall allows response packets only if they match an existing outbound connection.

---

## Stateful Inspection Flow Example

```

Client (192.168.1.10)
↓ SYN
Firewall (state: new)
↓ SYN/ACK
Server (8.8.8.8)
↓ ACK (state: established)

```

Only packets part of an **established** session are allowed.

---

## Comparing Inspection Methods

| Feature | Packet Filter | Stateful Inspection |
|----------|---------------|---------------------|
| Speed | Very Fast | Moderate |
| Context Awareness | None | Tracks sessions |
| Security Level | Basic | Medium-High |
| Suitable For | Simple routing/firewalls | Enterprise and cloud gateways |

---

## 5. Network Address Translation (NAT)

**Purpose:**  
Maps private IP addresses to public ones to conserve address space and conceal internal topology.

**Types of NAT:**
1. **Static NAT:** One-to-one mapping  
2. **Dynamic NAT:** Uses address pool  
3. **PAT (Port Address Translation):** Many-to-one mapping  

**Example (PAT):**  
```
192.168.1.10:45000 → 203.158.5.2:45000
```

---

## NAT Operation Diagram

```

[Internal Host] 192.168.1.10
↓
[Firewall NAT Table]
↓
[Public IP] 203.158.5.2
↓
[Internet]

````

**Benefits:**
- Hides internal IP addresses  
- Enables Internet access for LAN hosts  
- Adds basic layer of obfuscation  

---

## NAT Configuration Example (Cisco IOS)

```bash
Router(config)# interface g0/0
Router(config-if)# ip address 203.158.5.2 255.255.255.0
Router(config)# interface g0/1
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config)# ip nat inside source list 1 interface g0/0 overload
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255
````

**Explanation:**

* NAT overload = PAT
* Access-list defines internal IPs eligible for translation

---

## 6. Port Forwarding

**Definition:**
Redirects incoming traffic on a specific port to a designated internal host/service.

**Use Cases:**

* Remote access to internal web or SSH servers
* Hosting services behind NAT

**Example (home router):**

```
External: 203.158.5.2:8080  
Forward → 192.168.1.10:80
```

**Command Example (iptables):**

```bash
sudo iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to 192.168.1.10:80
```

---

## Port Forwarding Diagram

```
[Internet Client]
   ↓ 203.158.5.2:8080
[Firewall / Router]
   ↓ DNAT
[Internal Server 192.168.1.10:80]
```

## 7. Access Control Lists (ACLs)

**Purpose:**
Define rules controlling traffic based on IP, protocol, and port.

| Type             | Direction               | Description                          |
| ---------------- | ----------------------- | ------------------------------------ |
| **Standard ACL** | Source IP only          | “Permit 192.168.1.0/24”              |
| **Extended ACL** | Src/Dst + protocol/port | “Permit TCP 192.168.1.0 → Any eq 80” |
| **Named ACL**    | User-defined label      | Easier management                    |

**Rule Logic:** Top-down evaluation, first match wins, implicit deny at end.

---

## Example: Extended ACL (Cisco)

```bash
access-list 100 permit tcp 192.168.1.0 0.0.0.255 any eq 80
access-list 100 deny ip any any log
interface g0/0
ip access-group 100 out
```

**Meaning:**
Allow internal web traffic, deny everything else.

## Sample pfSense Rule Configuration

| Step | Interface | Action | Protocol | Source         | Destination | Port        |
| ---- | --------- | ------ | -------- | -------------- | ----------- | ----------- |
| 1    | LAN       | Allow  | TCP      | 192.168.1.0/24 | any         | 80 (HTTP)   |

## Troubleshooting Firewall Issues

| Symptom               | Possible Cause                 | Check                       |
| --------------------- | ------------------------------ | --------------------------- |
| No Internet           | NAT rule missing               | Verify NAT table            |
| Service not reachable | Port forward misconfigured     | Inspect DNAT entry          |
| Unexpected access     | ACL order incorrect            | Review rule priority        |
| Slow traffic          | Logging or inspection overhead | Adjust performance settings |

---

## 9. Firewall Best Practices

* Apply *least privilege* in rulesets
* Maintain **default-deny** policy
* Document rule changes
* Enable **logging and alerts**
* Perform regular audits
* Segment networks with VLANs and subnets
* Combine with IDS/IPS for full visibility

##Configuring a Basic Cisco Firewall

### Step 1: Define Interfaces and IP Addresses

```bash
Router(config)# interface g0/0
Router(config-if)# ip address 203.158.5.2 255.255.255.0
Router(config-if)# ip nat outside
Router(config-if)# no shutdown

Router(config)# interface g0/1
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config-if)# ip nat inside
Router(config-if)# no shutdown
````

**Concept:**

* `g0/1` = Inside network (LAN)
* `g0/0` = Outside network (Internet)

---

### Step 2: Configure NAT (Port Address Translation)

```bash
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255
Router(config)# ip nat inside source list 1 interface g0/0 overload
```

**Verification:**

```
show ip nat translations
show ip nat statistics
```

**Purpose:**
Enables LAN hosts to access the Internet through the router’s public IP.

---

### Step 3: Create Basic ACL Rules

**Example: Permit HTTP/HTTPS from LAN, Deny Others**

```bash
Router(config)# access-list 100 permit tcp 192.168.1.0 0.0.0.255 any eq 80
Router(config)# access-list 100 permit tcp 192.168.1.0 0.0.0.255 any eq 443
Router(config)# access-list 100 deny ip any any log
```

**Apply to Outbound Interface:**

```bash
Router(config)# interface g0/0
Router(config-if)# ip access-group 100 out
```

---

### Step 4: Configure Port Forwarding (Static NAT)

```bash
Router(config)# ip nat inside source static tcp 192.168.1.10 80 interface g0/0 8080
```

**Effect:**
External requests to `203.158.5.2:8080` are redirected to internal web server `192.168.1.10:80`.

---

### Step 5: Verify Configuration

| Task                    | Command                    |
| ----------------------- | -------------------------- |
| Check interface IPs     | `show ip interface brief`  |
| Review ACL hits         | `show access-lists`        |
| Confirm NAT translation | `show ip nat translations` |
| Review route table      | `show ip route`            |
| Display logs            | `show logging`             |

---

### Step 6: Save and Test

```bash
copy running-config startup-config
ping 8.8.8.8
```

**Expected Result:**

* LAN clients reach Internet via NAT.
* External users reach internal server via port forwarding.
* Only permitted traffic passes per ACL rules.

---

## Troubleshooting Cisco Firewall Configuration

| Symptom                     | Cause                  | Resolution                        |
| --------------------------- | ---------------------- | --------------------------------- |
| No Internet access          | NAT or ACL missing     | Check `show ip nat translations`  |
| Service unreachable         | Incorrect port forward | Verify DNAT rule syntax           |
| Access blocked unexpectedly | ACL order issue        | Re-order or insert rules properly |
| Interface down              | Admin-down state       | Run `no shutdown` on interface    |

## Step 1 – Configure Interfaces

```bash
enable
configure terminal
!
````

✅ Assign IPs to PCs and server in **Desktop → IP Configuration**.

## Step 2 – Configure NAT (Basic Firewall Behavior)

```bash
access-list 1 permit 192.168.1.0 0.0.0.255
ip nat inside source list 1 interface g0/0 overload
```

**Verify NAT:**

```
show ip nat translations
```

✅ Test from PC0:
`ping 203.158.5.2` → should succeed if NAT works.

## Step 3 – Apply Access Control List (ACL)

**Goal:** Allow only HTTP (port 80) to outside world.

```bash
access-list 100 permit tcp 192.168.1.0 0.0.0.255 any eq 80
access-list 100 deny ip any any log
!
interface g0/0
 ip access-group 100 out
```

✅ Test:

* **Browser (PC0)** → `203.158.5.2` (HTTP) ✅
* **Ping** external host ❌ (should be blocked)

## Step 4 – Observe with Simulation Mode
